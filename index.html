THE REASONING–ACTING GAP

能规划、能操作，是否就能完成整个任务？

面向真实任务的机器人操作模型与系统，需要同时具备两种能力：理解目标、利用历史并组织多阶段行动的推理能力，以及在时间、几何和接触约束下可靠完成操作的执行能力。分别具备这两种能力，是否足以保证完整任务成功，仍需要直接检验。

如果规划任务的执行过程被可靠的原子技能包办，就难以观察规划如何应对动作偏差；如果操作测试只要求完成一个短步骤，就难以观察执行结果怎样影响后续计划。两种评测各有价值，完整任务还需要检查它们之间的依赖。

REASONING

理解情境，组织行动。

结合观察、历史与规则，选择目标、安排顺序、判断阶段前提，并在条件变化时修订计划。记忆是支持这些判断的一种能力，研究范围也包括空间推理、任务拆解和进度维护。

当前应该做什么，哪些前提必须成立？

ACTING

满足约束，实现物理效果。

把目标转化为及时、精确、稳定的操作：在窗口内抓取移动物体，沿参考线维持接触，或将读数调到容差内。完成与否由实际效果决定。

这一步是否在时间与精度要求内真正完成？

从推理到执行的关键问题是：计划能否适应物理约束，
执行结果能否正确改变后续计划？

Mind2Act World 将这种双向依赖作为评测中心。推理决定当前操作的对象、目标、约束与时机；真实执行结果决定哪些目标仍待完成、哪些前提仍然成立，以及下一步是否可行。长程、记忆、精度和动态响应在同一流程中共同施加压力。

Reasoning 与 Acting 是评测视角，不要求模型采用显式双层架构。现阶段提供任务定义、演示和诊断设计；是否存在额外的协同瓶颈，需要由实验建立。

01 / THREE EVALUATION DIMENSIONS

Task-Level Reasoning · Constraint-Aware Execution
Reasoning–Acting Coordination

三个评测维度分别对应高层推理、低层执行与两者的推理—执行协同。Mind2Act 是推理与执行协同的项目品牌；World 是评测任务集合，Harness 是配套模型方案，并非额外的“世界模型”能力主张。

01MIND

Task-Level Reasoning

任务级推理：从情境中确定目标与计划。

高层推理把指令、观察、历史和规则转化为当前可执行的目标。

它需要识别任务对象、建立关系、安排顺序并维护阶段前提。记忆提供必要的历史依据，规划决定如何组织行动；环境状态变化后，还需判断原计划是否继续成立。

P · 订单配餐

新增订单改变累计需求，实际投放改变已完成量。被测系统要据此选择当前食材与容器，并维护剩余需求，避免遗漏和重复。

可检验证据对象与目标选择、顺序及前置条件是否正确；需求和进度是否一致。接口允许时，用可靠执行辅助检查原生决策，披露观察权限与预算。

02ACT

Constraint-Aware Execution

约束感知执行：在真实物理条件下实现目标。

目标正确之后，动作仍须满足时间、几何、接触与稳定性约束。

执行侧需要跟踪当前观测、选择操作时机并控制误差。这里的“约束感知”指行为能够适应可观察的物理条件，不要求模型输出显式约束表示，也不以控制命令结束代替实际完成。

PR3 · 大头笔描线

笔尖只有接触纸面才产生墨迹。三档保持路径长度与几何容差，增加转向要求，可检查轨迹偏离、断触与连续完成情况。

可检验证据实际读数或轨迹残差、有效接触、释放稳定性与端到端响应时延。正确子目标辅助的对照只适用于可替换接口，结果包含工具和控制器的贡献。

03COORDINATION

Reasoning–Acting Coordination

推理—执行协同：让计划与物理过程相互约束。

推理为执行确定目标与约束，物理结果为后续推理提供依据。

高层给出的计划约束执行，真实执行结果又反向改变剩余目标与阶段前提。独立子任务的简单串联难以检验这种依赖；需要明确执行后的哪一个状态改变了后续正确行为。

CP02 · 旋转蛋糕装饰

03 / DIAGNOSTIC PROTOCOL

从“失败了”，追问到“哪里失效”。

评测设计面向两类系统。它们共享任务目标与环境侧完成条件，并分别记录观察权限、动作接口、训练条件和时间预算。

诊断问题可观察的失败示例需要的证据
目标是否选对？订单需要薯条，却选择了汉堡选择对象、目标位置及任务条件；不能只依赖口述推理
正确目标是否实现？选对食品，但抓空或落在盘外有效抓持、释放与稳定入盘等环境事件
效果是否用于下一步？尚未入盘，后续行为却跳过这一需求动作前后状态及后续选择；内部状态不可见时保留归因不确定性

用对照检验假设。

可合法替换接口的系统，可比较原生决策＋可靠执行、正确子目标＋原生执行与完整系统；使用相同任务条件，记录各设置的信息权限、操作时长与预算。端到端模型使用可实施的观察或反馈干预。轨迹分叉后，分数差不能直接解释为纯粹的模块贡献。

面向两类系统，分别披露接口。

TRACK A

Coding Agents

模型根据观察与历史生成工具调用，通过声明的感知工具与执行接口操作机器人。关注目标选择、工具使用、反馈解释与任务推进。

观察与历史→Agent 决策→固定执行接口→物理效果
TRACK B

E2E VLA / WAM

学习式策略从声明的观察与指令输入生成动作或动作块。关注完整任务行为，以及历史、物理约束和执行反馈在连续控制中的作用。

观察与指令→VLA / WAM→动作块→物理效果

由环境侧判据确认完成。两条路径的接口和训练条件分别披露；协同要求描述的是任务依赖，不要求模型显式拆成认知与动作模块。

任务成功

最终物理状态满足任务目标及约束。

有效进度

当前仍成立的阶段完成条件与前置依赖。

物理残差

位置、角度、剂量或接触轨迹的任务特定误差。

时限与效率

交互吞吐、端到端时延及窗口错失。

恢复成本

偏差后的额外操作、时间和资源消耗。

持续环境时钟

动态场景需记录环境是否在模型推理期间继续推进。持续时钟与暂停推理条件分别报告，有效交互频率与控制器内部步频分别计算。

可解释的诊断

可替换接口的系统可使用认知侧或执行侧的 oracle 对照；其他系统可采用可实施的观察、反馈干预。按实际证据区分目标、动作和进度错误。

尚待验证：完整系统是否出现基础能力测试无法解释的失败？反馈干预是否影响进度更新和恢复？需先固定运行配置、标定阈值并完成重复实验；当前没有模型排名或协同瓶颈的实证结论。

COMPANION METHOD / ASTRA–JEV PROPOSAL

Mind2Act Harness

Contract-Guided Coordination of Cognitive and Reactive Agents for Robotic Manipulation

新版方案聚焦成本感知的 Astra–Jev 协同：GPT-6 Astra 拆解子任务并调用感知工具，harness 将结果、候选与工作记忆编译为结构化文本，Jev 选择当前适用候选，由 Runtime 核验后执行。

Evidence-Grounded State

交接保留观测来源、坐标系、时效和未知项，区分动作回执与实际效果。

Candidate-Constrained Jev

Budgeted Memory & Routing

保留任务关键事实，按事件局部刷新或升级 Astra，计入所有感知、摘要、重试与执行成本。
