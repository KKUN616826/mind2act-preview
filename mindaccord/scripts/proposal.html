Mind2Act Harness

__SUBTITLE__

让可复用的理解支持行动，
让新的执行反馈决定认知需求。

多步机器人操作中，任务目标可能保持不变，行动所依赖的证据却会改变。Mind2Act Harness 研究如何分配视觉推理：Cognitive 提供可见事实与短期意图，Jev 根据回执选择工具、补观察、读取信息或请求重规划，视觉执行工具完成连续控制。RSI 将开发反馈转为经过验证的跨局经验与策略改进。局内决定下一步，局间改进协作方式，共同追求任务能力、成本和完成时间的改善。

01 / THE RESEARCH QUESTION

目标可以复用，执行依据需要更新。

GPT-6 Astra 这类视觉工具 Agent 可以解释任务并调用机器人，但动作会改变场景，重新看图和推理又需要时间。每个工具边界都完整重想可能产生冗余开销；长期沿用旧计划，则可能在目标移动、遮挡变化或执行失败后继续使用失效依据。

核心 insight 是：语义目标与局部执行证据可能以不同速度变化。 一次失败可能只需要局部测量，也可能需要重新理解场景。研究问题是如何依据反馈选择所需推理层级，而不是预设双 Agent 一定更快。

Jev 的作用是让一次 Cognitive 理解支持多次局部选择，并将信息获取和升级纳入选择范围。文本交接、候选构造与额外调用也有成本；若每次仍需 Astra 完整看图，或规则已足够可靠，增加 Jev 可能没有收益。

不同布局和任务还可能反复暴露相似的交接与工具使用问题。RSI 进一步研究：系统能否依据自己的开发记录，提出并验证改进，让下一局使用更合适的经验与协作策略，而不依赖逐次人工修改。

局内调度与局间改进是相连的研究方向。已有机制的组合不自动构成创新；协作与自我改进收益均需独立验证。

02 / METHOD

短期意图、局部选择与连续控制分工协作。

Cognitive 负责视觉理解与计划修订；Jev 根据当前报告与新回执决定下一次工具调用；视觉工具负责动作内部控制。Runtime 管事件、授权和取消，独立评分器在结束后判断实际结果。下图展示局内分工；局间 RSI 由独立 Critic、验证器与版本管理连接到后续任务。

回应必须再次校验，才能进入物理执行。

  1. 编译保留来源，拒绝未知单位与过期绑定。
  2. 选择一次选择一个完整候选，避免独立参数错误拼接。
  3. 复核响应回来后重新检查目标版本、时效和预算。
  4. 执行唯一动作入口派发；实际效果另行确认。

合法候选不等于物理上必然成功。confidence 不能代替真实抓取、放稳或触发证据；最终任务结果由独立环境判据确认。

04 / EPISODE-LOCAL MEMORY

Jev 决定记什么，程序如实记录动作。

Jev 每次读取提交的文本状态。动作记忆的保存、读取和删除由 Jev 主动选择，确定性程序提取固定字段；Cognitive 持久会话独立维护，不代写动作记忆。

05 / FEEDBACK-DRIVEN COGNITIVE UPDATES

从执行反馈判断需要哪一层支持。

Jev 在新回执或新报告到达时选择工具；无事件时等待。执行中不逐运动阶段重复询问模型。局部信息不足时可以补观察，意图或指代需要修订时可以升级 Cognitive。

06 / NEAR-TERM RSI

局内反馈指导行动，跨局反馈改进协作。

RSI 是紧接当前原型的实现重点。复用原双 Agent 的开发记录、Critic、经验候选和验证发布基础，先接通认知与工具使用双经验库，再扩展受限的交接和调度补丁。当前是待实现设计，不声明 Jev 已具备自主改进收益。

  1. 记录与归因独立 Critic 读取合法开发记录，先核对实际回执，识别重复问题。
  2. 提出改进生成带来源、适用条件和父版本的经验卡或策略补丁。
  3. 隔离验证比较父版本与候选的闭环效果；无收益或有退化则不激活。
  4. 版本化复用后续局使用固定快照；退化时回滚，新开发记录支持下一轮。
改进对象作用接入顺序
Cognitive 经验改善可见事实、意图交接与重规划判断首版双经验库
Jev 工具使用经验辅助判断信息缺口、工具回执、重试与升级首版按需读取；Agent 仍决定动作
交接与调度补丁修改声明范围内的提示、编码或调用配置经验闭环接通后扩展，独立验证

每局固定一个策略与经验版本，局内动作记忆仍从空开始；Critic 不控制实时机械臂。只向在线 Agent 开放已验证经验索引和主动读取，不把旧场景答案、隐藏布局或私有坐标写入经验。

验证与正式测试不进入改进队列，正式测试期间冻结版本。评分器、观察权限与授权协议不属于候选可修改范围；改进成本包括 Critic、验证及失败候选。首个里程碑是完成一次有证据的候选接受或拒绝闭环。

07 / TASK REQUIREMENTS

目标在一段时间内稳定，反馈会改变下一步选择。

这类多步任务允许复用部分理解，同时要求识别局部信息不足或计划失效。长程本身不保证需要复杂策略；无分支流水线可能只需规则，每步都需新语义理解的任务也可能没有认知复用空间。

案例任务特性主要待验证点
Case7 清框原型多次搬运共享目标，动作改变可见区域已有可运行证据；尚不足以证明强记忆或动态时限能力
E / P身份、累计需求与实际完成量反馈后的任务进度，不能以命令结束替代入盘
S / M / F空间绑定、完整顺序与映射假设观测消失后的信息保持与更新
FR1 / FR2目标明确但有运动窗口控制语义难度后，端到端吞吐是否改善
PR1 / PR2 / PR3精确轨迹、接触与实际残差执行器是前提，调度不能替代精细控制
CP01 / CP02订单／布局相对稳定，目标位置与实际效果变化认知复用、局部刷新与动态窗口的取舍
其他组合任务按规范确定配方、空间或序列依赖接入环境与判据后再测，不宣称已经覆盖

08 / EVIDENCE & EVALUATION

原型验证可运行性，对照检验协作收益。

Case7 清框原型已完成视觉理解、工具选择与机器人执行的闭环，并实现全部拼块出框。开发迭代减少了部分重复调用，但尚未体现整体加速、Cognitive 调用减少或主动记忆收益。同一场景的结果仍不足以证明优于单 Agent 或跨任务泛化。

局部选择

固定报告、候选与工具，对比 Jev、Astra 和规则选择，检验下放决策是否值得。

认知更新

固定选择器与执行工具，对比频繁更新、现有固定触发和按需升级。

整体收益

与同工具的单 Astra Agent 比较，在独立布局及动态反馈任务中检验成功率、总成本和完成时间。

各组保持一致的输入权限、工具能力与资源预算，保留失败记录；记忆和异步机制单独消融。RSI 比较冻结版本与同等开发预算下的自主更新版本，计入改进开销，并在冻结的独立测试中检查收益与退化。详细运行记录见 开发证据。

实现范围、开发证据与正式评测分开记录。
