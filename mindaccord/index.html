MindAccord

Contract-Guided Coordination of Cognitive and Reactive Agents for Robotic Manipulation

任务层保持目标与计划，动作层处理当前执行，物理反馈连接两者。以 EvoMemHarness 为实现基础，通过版本化子目标契约、唯一执行入口与取消确认协议协调 Cognitive 和 Reactive，连接长程推理与局部执行。

01 / SYSTEM ARCHITECTURE

从任务意图，
到局部执行。

Cognitive 维护任务与授权，Reactive 决定当前动作。两者共享观察与按需工具，物理执行由 Runtime 统一派发，执行结果再返回双方。

已实现 · 原生协议

Cognitive Agent

维护长程目标和有效进度，决定当前应完成哪个子目标。可以在 Reactive 执行期间推理后续计划；普通笔记和无关未来计划更新不应撤销正在执行的授权。

INPUT
任务文本、当前 RGB / 本体状态、执行事件、局内笔记
OUTPUT
任务依赖图、当前子目标、版本化授权与计划修订

不直接提交物理动作；完成声明属于模型判断。

02 / ONLINE COORDINATION

执行在继续，
认知也在更新。

两个 Agent 独立运行，按事件交换进度。任务计划、动作回执和效果判断具有不同含义，只有一致的授权与证据才能支持下一步。

  1. 01 / AUTHORIZE

    确定当前子目标

    明确目标、允许工具、约束与预算，发布稳定的授权版本。

  2. 02 / EXECUTE

    派发有限动作

    Reactive 提交动作或最多八步的批次，由 Runtime 核对后执行。

  3. 03 / OBSERVE

    在检查点重观察

    保留动作回执和来源帧；按需判断效果、补充信息或请求恢复。

  4. 04 / RECONCILE

    更新任务与授权

    根据反馈维持、修订或撤销子目标，让下一动作与当前任务一致。

当前执行继续，任务层可规划后续

Cognitive

保持当前子目标的授权，利用已有反馈维护未来依赖。无关计划变更不打断当前动作。

Reactive

等待动作回执，或在显式检查点接收新观测，再决定下一步。

Runtime

独占动作入口，逐步派发并记录实际执行量；推理期间环境仍可继续推进。

动作已派发、正在执行与子目标已完成是不同状态。

03 / TRACE-GROUNDED EXPERIENCE

把经历沉淀成经验，
需要一道验证边界。

认知经验改善任务决策，运动经验改善局部执行。两者共享可追溯的执行记录，但分别保存适用条件、归因与验证结果。

局内：保留正在使用的状态

Private / Shared Notes 保存本局的目标、假设和进度。Agent 主动读写正文，版本检查避免覆盖冲突；笔记不自动成为跨局经验。

跨局：复用经过验证的经验

开发记录进入离线 Critic，形成认知或运动候选。候选只有通过适用范围内的验证，才能写入冻结快照供后续 Episode 使用。

认知经验保存什么

任务拆解、证据解释、前置依赖和恢复判断。指向何时采用、何时拒绝某种决策原则。

运动经验保存什么

局部动作与参数选择、失败模式和恢复条件。当前 motor 卡和独立程序修复试点还不等于训练好的 VLA。

SEM-Memory 的后续位置

利用独立 command-effect evidence 建立效果后验，再提出受限残差。支持域、校准与回滚仍需接入验证。

代码边界：原生 Critic 当前保留候选，尚无成对原生回放与回归验证；新的 RGB 原生运行要求空经验快照。图中的验证后晋升路径属于待完成的原生闭环。

同一能力框架，
不同模块承担责任。

MindActWorld 定义要测量的能力，模型页说明实现这些能力的组织方式。具体任务、难度与演示统一保留在 Bench 页面。

评测维度模型模块目标能力需要观察的证据

Constraint-Aware Execution · 约束感知执行Reactive + 执行后端精度、响应与持续接触记录实际物理误差、执行时延与有效交互频率。
Reasoning–Acting Coordination · 推理—执行协同Contract + 执行反馈效果驱动的进度推进检查是否根据实际执行反馈修订后续决策。
迁移（附加协议）Cognitive / Motor Experience冻结经验的跨局复用在独立实例上比较首次表现、恢复成本与负迁移。
