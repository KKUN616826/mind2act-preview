# MindAccord · Proposal v2

**Contract-Guided Coordination of Cognitive and Reactive Agents for Robotic Manipulation**

研究方向：**Cost-Aware Astra–Jev Coordination through Structured Perception and Bounded Working Memory**。

版本：v2。状态：新架构提案，尚未完成 Astra–Jev 端到端接入、机器人评测或成本收益验证。GPT-6 Astra 为指定上游配置名称；实际 API 模型标识、Jev 固定版本和计费项在运行前确认。此文不提供推测价格或性能。

## 1. 研究问题与三个设计假设

如何把高层视觉推理转化为可复用、可追溯的局部决策状态，使下游模型以受限上下文完成操作，并在保持任务表现的条件下减少总调用成本？

1. **Evidence-Grounded State Compilation · 带证据的状态编译**：Astra 将任务拆为子目标并调用 perception tools；harness 把工具结果、对象绑定、完成条件与合法候选编译成 Jev 可读的结构化文本。关键信息不能在压缩时被无声丢弃。
2. **Candidate-Constrained Reactive Decision · 候选约束的局部决策**：Jev 选择完整候选 ID；连续参数和工具调用由注册表与执行适配器绑定、校验。类型正确不等于物理正确，未知或失效的候选不得执行。
3. **Budgeted Working Memory and Routing · 有预算的工作记忆与调用路由**：保留未完成目标和有依赖的历史，限制每次请求的原始事件窗口。按事件决定继续执行、局部刷新、询问 Jev 或升级 Astra，而非每步重复完整高层推理。

三个假设都需要消融与闭环实验。当前主线不包括 RSI、跨局经验晋升、自进化或权重更新；VLA 后端可作为未来扩展，非本轮收益成立的前提。

## 2. 整体架构

![Astra–Jev 总体架构](../figures/architecture.svg)

**任务 / 观察 → Astra 子目标与感知请求 → perception tools → State Compiler + Candidate Registry → Jev 选择 → Runtime / 控制器 → 新观察与回执**。

Cost Router 管理调用策略与预算。Astra 负责复杂任务解释、视觉歧义和计划修订；Jev 负责结构化状态下的局部选择；数值比较、权限、时效、预算和动作派发由代码处理。Jev 不承担图像理解或关节伺服。

此前 EvoMemHarness 快照中的授权、单一执行入口、取消确认与局内 notes 可以作为工程基础，但它们不等于下文的新状态编译器、候选注册表、Jev 适配器和成本路由已实现。

## 3. Astra 如何形成可交接的子目标

输入包含任务指令、当前可见观察、任务状态与待解决事件。输出分为可独立更新的三部分：

- **SubgoalContract**：episode_id、goal_id、contract_version、当前目标、前置条件、工具许可、完成条件、检查点与预算。复杂任务形成依赖图；无关未来计划更新不必撤销正在执行的授权。
- **PerceptionPlan**：明确要观察的对象或属性、需要的分割 / 深度预测 / 跟踪 / 测量工具，以及证据刷新条件。工具调用的开销计入总成本。
- **TaskMemory**：订单需求、已支持的完成事件、路线或示范序列、阶段索引、未完成依赖。自由解释与精确账本分开保存。

Astra 不必每次为 Jev 重新看图。它可以在子目标授权中规定允许复用的感知调用和技能模板，后续由事件触发局部刷新；遇到新对象、身份歧义或计划冲突再升级。工具复用能否降低成本，是待测假设。

## 4. Perception 到结构化文本：保留什么、拒绝什么

![交接与工作记忆](../figures/packet-memory.svg)

工具输出的 **SceneState** 至少需要以下字段：

| 字段 | 作用 | 失效或缺失时 |
|---|---|---|
| observation_id / timestamp / source_tool | 追溯事实来自哪一帧与哪次工具调用 | 不把无来源文本作为新观测 |
| entity_id / identity_binding | 关联目标和当前对象 | 身份不确定则保留 unknown，并重新确认 |
| value / units / coordinate_frame | 区分像素、相机坐标、基座坐标和物理量 | 缺单位或坐标变换时禁止绑定运动目标 |
| uncertainty / validity / invalidated_by | 表达不确定性与场景变化 | 根据变化失效，不仅依赖固定 TTL |
| last_action_receipt / effect_evidence | 区分动作调用结束与目标实际达成 | 未确认时不推进完成状态 |

所有字段必须来自策略允许访问的观察。感知预测不是模拟器真值；不得把物体 GT pose、评分器标记或不可见状态偷偷写入文本。

相机坐标必须通过声明的、允许使用且经验证的变换关联到控制坐标。若当前观察条件无法提供所需标定或变换，标记该动作不可绑定；由合法的估计、交互标定或升级流程解决，不能补造基座坐标。

不把多次观测盲目拼成一个“当前帧”：每个事实保留自己的时间与来源。对象消失也不意味着已成功提交。对持续运动场景，身份、位置和速度证据有不同的有效范围。

## 5. Jev harness：完整候选选择，而非任意动作生成

官方 State 文档说明 Jev 接收文本状态，支持字符串、JSON 对象或数组，不接收图像/视频。Choice 从指定选项中作选择。请求结构与模型限制见文末官方资料；Jev 版本与限制需在实验冻结前复核。

因此，harness 需要提供以下组成：

1. **Typed State Compiler**：合并契约、有效 SceneState、记忆与回执；确定性计算数量差、时间和预算。将 unknown 显式传递，记录输入截断或压缩。
2. **Candidate Registry**：每个 candidate_id 绑定一个完整、不可变的动作或技能请求，包含执行器、数值参数、单位、坐标来源、前置条件、期限与授权版本。候选提供者可以是可复用技能加感知绑定，或 Astra 生成的受验证局部程序；必须计入其成本。
3. **Jev Adapter**：将当前合法候选和 criteria 编成 Choice 请求，返回候选 ID 及服务提供的统计信息。不让 Jev 分别选手臂、坐标和姿态后随意拼接；多问题的独立答案不保证联合可执行。
4. **Post-response Guard**：Jev 返回后再次核对授权、证据版本和时效。过期结果丢弃；概率或 confidence 不作为物理成功的证明。
5. **Execution Runtime**：唯一动作入口、去重、有限批次、检查点与取消确认；健康动作在执行中由事件循环延续，不为“继续”等确定性步骤额外调用模型。

协议合法不代表无碰撞或一定成功。候选生成器与执行器必须披露实际覆盖的能力和检查边界。若无法为某个 case 产生足够的可执行候选，先报告覆盖缺口，不能假定 Jev 会自行补全动作。

本页提供的是**合成协议示例**，不是运行日志或成功轨迹。SceneState 中变换未知时只提供感知刷新、升级和停止等非运动候选；示例不以虚构坐标伪装已接通控制接口。

## 6. 记忆窗口与记忆文本

“窗口”限制每次请求带入多少历史，不应删除仍然必要的任务事实。提出四类记忆：

| 类型 | 内容 | 保留 / 失效策略 |
|---|---|---|
| Pinned task facts | 未完成订单、规则、完整待执行序列、前置依赖 | 按依赖保留，不能因窗口变短而丢失；任务结束后清理 |
| Recent event window | 最近 K 个观测、动作回执、失败与效果判断 | K / token 预算在开发集选择；保留来源索引 |
| Evidence-linked memory text | 更早事件的带来源摘要与待确认假设 | 摘要不能覆盖精确账本；矛盾触发复核，不取“最新文本即真值” |
| Live scene cache | 当前对象位置、跟踪状态与接触证据 | 随运动、遮挡、重置或身份变化失效；不得从历史摘要直接恢复旧位姿 |

Jev 是逐请求读取提交的 state；会话记忆由 harness 管理。自由文本摘要由 Astra 或独立声明的摘要模块生成，不能让 Jev 凭空写记忆。收缩上下文前优先裁剪无关历史；若关键事实无法装入预算，应检索、分阶段处理或显式升级，不能无声截断。

任务进度来自具有证据引用的在线判断。确定性账本保证事件去重和索引一致，不保证感知判断永远正确；离线环境 scorer 独立核验任务成功。

## 7. 成本感知调用与刷新

![事件驱动的调用决策](../figures/routing.svg)

| 状态 | 首选路径 | 成本原则 |
|---|---|---|
| 健康动作在有效授权下运行 | Runtime 等待回执或检查点，不询问模型 | 不为确定性延续付出额外调用 |
| 几何证据过期、绑定缺失 | 执行已授权的局部感知刷新；必要时升级 Astra | 不用过期状态换取低 token 成本 |
| 状态有效且存在多个语义候选 | Jev 选择完整 candidate_id | 输入中只带当前决策所需事实 |
| 无适用候选、身份歧义或子目标冲突 | Astra 重新 grounding、扩展候选或修订计划 | 防止廉价层反复失败积累更大开销 |
| 剩余预算不足以取得必要证据 | 停止、等待或返回预算耗尽 | 不降低关键检查标准、不把未完成记为成功 |

Confidence 阈值需在开发集根据错误代价和覆盖率选择，测试前冻结；高置信度也可能来自“一组坏候选中的相对偏好”。缺数据时采用可审计的规则路由，不宣称已经学到了最优路由策略。

**成本账本**：C_total = C_Astra + C_perception + C_candidates + C_Jev + C_summary + C_retries/fallback + C_execution。API、GPU/工具计算和仿真资源分别记录；同一次调用只计一次，缓存命中与实际计费口径需披露。

同时报告所有尝试的平均成本、总成本 / 成功 episode 数、失败/超时率和任务成功率。成功数为零时，该比值未定义；失败与升级产生的费用不能从分子排除。性能目标是满足预先声明的任务质量和时限约束后比较成本，而不是用频繁提前放弃制造“省钱”。

异步执行时使用真实关键路径和完整 observation-to-action 延迟；不能简单相加并行耗时。环境是否在模型推理期间继续运行、time_scale、机器负载和 API 地域均需固定并报告。厂商延迟不是我们的控制频率保证。

## 8. 与当前案例对应

| 任务 | 必须保留的信息 | 候选 / 刷新难点 |
|---|---|---|
| E / P | 已见身份、订单累计量与实际完成量 | 相似物体绑定；投放失败不扣减需求 |
| S / M | 颜色—格位绑定、目标路线和重复到访 | 旋转 / 交换更新索引；完整待执行序列不受短窗口淘汰 |
| F | 未知按钮映射假设及有效试验结果 | 无效按压不能记为规则证据；当前局内映射保持固定 |
| FR1 / FR2 | 有效窗口、当前提示、取件 / 释放状态 | 动态证据刷新；端到端时延决定能否赶上窗口 |
| PR1 / PR2 / PR3 | 目标读数、参考轨迹、实际残差或接触 | 候选参数与坐标绑定；精细控制由后端完成 |
| CP01 / CP02 | 订单 / 局部位置绑定、剩余目标与阶段前提 | 运动使位姿快速失效，局部更新机制必须验证 |
| CP03 / CP04 / CP05 | 当前规范中的配方、空间依赖或复奏序列 | 部分场景/规范仍需核定；不宣称本方案已覆盖全部 case |

初期优先选择已有可运行环境和明确判据的代表任务；网页素材数量不等于已接入或已测量的任务数量。

## 9. 匹配输入的评测与消融

| 组别 | 配置 | 回答的问题 |
|---|---|---|
| A | Astra 主导的完整原始执行流程 | 系统级成本与任务表现基线 |
| B | 相同结构化状态 / 候选 + 规则选择 | 这些决策是否需要模型 |
| C | 相同状态 / 候选 + Astra 仅输出 ID | 排除提示词长度或输出格式导致的不公平差异 |
| D | 相同状态 / 候选 + Jev，每个决策事件刷新 | Jev 选择器本身的表现 |
| E | D + 有界工作记忆 + 事件刷新 / 升级策略 | 完整方案是否改善成本—成功率权衡 |

B–E 共享感知、候选提供者与评测权限。对照固定数据种子、任务版本、成功判据、动作预算、时钟、并发和资源设置。A 与其他组是系统比较，不能直接将差异归因为 Jev。

消融分别移除 pinned facts、使用原始长历史、取消事件驱动缓存、取消低置信度升级、改变 K 和刷新阈值。失效检查始终保留；不以执行已知过期动作作为正常评测配置。

先做无动作的 trace / 影子评估，检查信息损失、候选覆盖、过期率与决策延迟；真实收益必须通过在线闭环确认。参考模型答案一致不等于物理正确。报告逐任务/难度结果、运行数和区间，当前所有结果均待测。

## 10. 实施顺序与退出条件

1. 采集当前 Astra 路径的原始事件、模型输入、感知调用与账本，确认可转成候选选择的真实决策点。
2. 实现契约、带来源状态与完整候选的 schema / adapter；用合成数据验证时效、版本、缺失变换和拒答路径。
3. 做 Jev 影子选择，统计覆盖缺口，再在少量明确任务上接入 Runtime。
4. 接入有界记忆与成本路由，保持 baseline 相同输入与工具支持；冻结开发阈值后运行独立测试。
5. 如果每次 Jev 调用都需要 Astra 完整重做视觉推理，或总成本/尾延迟没有改善，就保留该负面结果并调整分工。不得仅凭 Jev 单价得出系统收益。

需要固定的参数包括上游 API 模型标识、Jev 版本、候选生成器、允许的坐标变换、记忆预算、刷新触发、升级阈值与每局预算。这些是实现配置，不是当前已测结论。
