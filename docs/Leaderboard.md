## 三个视图

1. **能力概览**：预留名次、综合分、认知核心、动作核心和耦合套件结果。
2. **逐任务结果**：覆盖 E/P/S/F/M、FR1/FR2/PR1/PR2/PR3、CP01–CP05，列标题可跳转到任务定义。
3. **运行与成本**：预留回合数、端到端时延、任务运行时长、API 成本。API、GPU 与仿真成本须分开报告；不适用项与缺失项应明确区别。

所有数值均为 JSON `null`，页面显示“—”。`null` 不参与平均，不转成 0，也不生成名次。

## 实测成绩发布前

需要先固定环境与任务版本、难度/种子、成功判据、观察权限、训练与微调条件、动作接口、时钟和预算。每个结果应关联运行日志、样本数、不确定性估计和复现配置。

综合分聚合方法目前未定。应先定义各任务与难度的权重，以及缺失或不适用结果的处理方式，再实现计算。不要把不同覆盖率或不同协议下的数值直接混合排名。VLA/WAM 与 Coding Agent 保持分榜；跨系统解释应披露工具和执行支持差异。

`scripts/leaderboard.py` 当前主动拒绝非空成绩、名次、回合或成本。发布实测成绩时，需要同时升级数据协议、计算逻辑、呈现状态和验证测试；不能直接把待测字段填数后沿用占位视图。
