# PhysCo：高层认知与肌肉记忆，共同完成物理任务

面向未来 Embodied Agent，评估理解任务、熟练行动与持续协同的能力。

PhysCo 将目标选择、物理执行与状态更新放在同一条任务链中考察。15 项任务分别提供认知、动作和耦合三个观察入口，研究历史信息、动态时机与接触约束如何共同影响完整任务的完成。

当前内容是任务设计、运控演示与评测协议建议。以下观点属于设计出发点和待检验假设，尚无模型比较结果支持能力瓶颈的归因。

## 为什么需要 PhysCo

未来的具身智能体需要在目标变化、信息不完整与物理结果不确定的条件下完成任务。一次抓放是否成功，只回答了其中一小部分：它还需要理解为什么抓、记住此前发生了什么、判断什么时候该换一种做法，并在连续执行中保持这些判断有效。

[RoboDojo](https://robodojo-benchmark.com/) 的研究动机强调，短程、技能覆盖较窄和操作模式相似的任务难以全面刻画通用操作策略。PhysCo 进一步聚焦两种相互依赖的能力：

- **高层认知**：把观察和历史转化为任务状态，维护身份、数量、规则与关系，据此确定对象、顺序、阶段前提和剩余目标。当条件改变时重新判断计划是否仍然成立。
- **肌肉记忆**：通过学习或练习形成的感知—动作技能，体现为抓持、调节、跟踪和接触中的时机、精度与稳定性，将抽象意图转化为可靠的物理效果。

“肌肉记忆”是习得动作技能的功能性表述，不指定生物机制、显式记忆模块或特定网络架构。动作核心检验其行为表现；技能如何习得、保持和迁移需要额外的训练及跨任务实验。固定控制器辅助的 Coding Agent 成绩也不能直接证明基础模型具备了习得的动作技能。

两种能力在执行中持续交换约束与结果。记住蛋糕的局部位置，还需随旋转更新实际落点；规划装箱顺序，还需考虑放置后的姿态和剩余空间。反过来，抓空不能扣减订单，未归位的工具不能被当成已经可用。评测应同时追问目标是否合理、动作是否达标，以及实际效果是否用于下一步。

**PhysCo 的意义在于刻画这种协同所需的能力结构，并为失败提供可检验的诊断入口。** 三组任务提供能力剖面；同任务受控对照和过程事件用于区分认知、执行与状态更新问题。不同套件的分数差本身不构成因果证据。

RoboDojo 也强调仿真与真实世界评测的互补性。PhysCo 当前的仿真素材与评测设计侧重可控、可复现的诊断；尚未发布统一 sim-to-real 对照，不能由演示直接推断部署可靠性。

## 1. 核心观点

### 高层：历史与规则决定此刻的目标

当关键线索已经离场，机器人仍需知道该选谁、放哪里、按什么顺序做。高层认知需要维护已见身份、累计需求、空间绑定、控制规则和事件顺序，并把这些信息用于选择对象、位置、约束和剩余目标。

例如，P 订单配餐中的新增订单改变“应该放多少”，真实投放改变“已经完成多少”。两者需要分别维护。E/P/S/F/M 分别提供身份、数量、空间、映射与路线记忆的观察入口。高层正确性应由选择和行为证明，不能仅凭模型口述推理判断。

检验方式：固定物理条件，改变历史负担；接口允许时，用可靠执行器辅助检查原生认知决策。感知歧义、目标错误与抓放失败需分别记录。

### 肌肉记忆：熟练动作如何应对时间与接触约束

知道该抓哪个物体，还需要及时抓到；知道目标读数，还需要松手后仍然达标。FR1/FR2 检查动态窗口和事件响应；PR1/PR2 检查调节后释放稳定性；PR3 检查真实笔尖接触产生的连续墨迹。

检验方式：在目标明确时记录残差、有效接触和端到端延迟。动态任务需说明模型推理时环境是否继续推进；控制器内部步频与有效交互频率分别报告。剂量、接触和几何阈值必须经标定后用于模型比较。

### 耦合：物理效果会改写下一步的目标与计划

认知为执行指定目标和约束，执行结果再决定哪些目标仍待完成、哪些前提仍然成立。闭环的关键，是让“打算完成什么”持续与“实际完成了什么”保持一致。

- CP01 配餐：真实入盘后才能扣减对应订单的剩余需求。
- CP02 装饰：把记忆中的蛋糕局部位置转换为随旋转变化的当前目标；真实落位与实际停稳决定后续操作。
- CP03 配液：本步实际剂量和工具归位状态决定下一阶段是否可以推进。配方全程可见，不将隐藏配方记忆作为核心。
- CP04 打包：实际物品姿态与空间占用会影响余下布局和盖合，必要时需重排；实例难度仍待验证。
- CP05 复奏：独立有效触键才推进序列；主体结束后仍需归棒，Medium/Hard 还需合盖。执行不要求跟拍。

检验方式：对齐“当前目标—实际效果—下一步行为”的事件轨迹，使用可实施的目标、执行或反馈对照。单项测试和完整任务的分数差，尚不足以证明额外的耦合瓶颈。

## 2. 任务怎样检验这些问题

| 入口 | 核心问题 | 任务 |
|---|---|---|
| 认知核心 | 目标是否正确？ | E / P / S / F / M |
| 动作核心 | 效果是否达标？ | FR1 / FR2 / PR1 / PR2 / PR3 |
| 耦合套件 | 下一步是否仍然成立？ | CP01–CP05 |

三个入口不等于严格隔离的能力测量，也不限定模型必须采用双模块架构。认知任务仍需物理执行，动作任务仍需感知与目标理解；归因需依赖同任务对照及过程证据。

| 压力维度 | 证据要求 | 不能直接据此推断 |
|---|---|---|
| 记忆与规则 | 当前观察之外的信息用于选择对象、目标与顺序 | 指令长、对象多，不自动构成记忆依赖 |
| 长程与规划 | 阶段前提、有效进度和偏差后的计划修订 | 重复抓放次数多，不自动证明复杂规划能力 |
| 动态响应 | 运动窗口、端到端延迟与有效吞吐 | 模拟器步频高，不等于模型实时响应 |
| 精细与接触 | 实际读数、轨迹、剂量、间隙与触发约束 | 动作轨迹看起来准确，不等于效果达标 |

CP01 的动态响应压力需标定；CP02 的现有档位同时改变数量、转速和动作链，单因素归因需另设控制变量切片；CP03 的液体剂量需标定；CP04 的空间难度需实例验证。CP05 不作为独立频率压力证据。

## 3. 从失败走向诊断

| 诊断问题 | 失败示例 | 所需记录 |
|---|---|---|
| 目标是否选对？ | 订单需要薯条，却选择汉堡 | 对象、目标位置、任务条件 |
| 正确目标是否实现？ | 选对食品，但抓空或落在盘外 | 有效抓持、释放、稳定入盘事件 |
| 效果是否用于下一步？ | 尚未入盘，后续行为却跳过该需求 | 前后状态与后续选择；无法区分时保留不确定性 |

以上是诊断示例，不是已观察到的模型失败统计。

对可合法替换接口的系统，比较原生决策＋可靠执行、正确子目标＋原生执行与完整系统，并固定任务条件、披露信息权限、操作时长和预算。可靠执行不得直接替高层解答隐藏历史；正确子目标不得提前泄露未来事件。端到端模型采用可实施的观察或反馈干预。轨迹分叉后，分数差不能直接解释为纯粹的模块贡献。

Coding Agents 与 E2E VLA/WAM 共享任务目标与环境侧判据，分别披露动作接口、训练条件和时钟条件。最终成功率应结合分阶段成功、物理残差、时限和恢复成本报告。

## 4. 当前证据与开放问题

本仓库已提供 15 项任务定义、难度设置、37 段演示及预览、2 张场景图和评测设计。统一可运行环境、评测接口和模型对照结果尚未在此发布。

CP03 为倒液与搅拌局部预览，CP04 目前只有场景图；P Easy/Medium 视频待补。CP05 三档完整流程视频已提供，Easy 无琴盖，Medium/Hard 包含开合盖。演示只说明所展示场景及流程，不代表随机实例可解性、模型成绩或能力归因。

待验证的问题是：完整系统是否出现基础能力测试无法解释的失败？执行偏差是否通过错误进度更新放大？可实施的反馈干预是否影响恢复？这些结论需要重复实验与对照证据。

[技术报告 v0.1](PhysCo_Technical_Report_v0.1.pdf) 提供早期研究框架，具体任务以当前定义为准。

## 5. 排行榜与候选系统

VLA/WAM 与 Coding Agent 分榜呈现。VLA/WAM 计划包括 hyVLA、dm0.5、g0.5、openwam、pi0.5；名称按用户评测计划保留，checkpoint 与动作接口待固定。Coding Agent 候选名称和参考 harness 取自 RLE-Bench 的公开名单，完整列表见 [排行榜协议与候选说明](Leaderboard.md)。

所有条目目前均为待评测，分数、回合数、成本、时延和排名字段为空。三套件表现、逐任务结果、运行成本分别预留，综合分聚合方法尚未冻结。两条路径的信息权限、训练条件和执行支持需分别披露后再解释比较结果。
